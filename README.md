# Projets LFS

## Overview

**Projets LFS** is the educational project management platform of the Lycée Français de Séoul (LFS). Developed in Python with the Flask framework, it offers the administration and teaching staff a centralized collaborative space to create, validate, and track projects and their budgets.

## Features

* **Role and access management:**
    * *Teachers:* Creation, duplication, submission, and history tracking of their projects.
    * *Management & Administrators:* Review, validation, budget code management, and overall supervision.
* **Comprehensive project forms:** Centralized data entry (educational objectives, skills, student groups, budget by calendar year, logistical information).
* **School trips:** Automatic generation of formatted trip forms (e.g., for the embassy).
* **Collaborative tools:** Integrated messaging for each project and automatic email notifications during key events.
* **Exploration and analysis:**
    * Advanced search and filtering (year, department) with role-based visibility.
    * Statistical dashboards and interactive charts (school project and timeline).
    * Budget management with database export to a spreadsheet.
    * Dashboard for administrative management.
* **Authentication:** Standard login (username/password) or via Google OAuth (SSO).

## Technologies Used

* **Backend:** Python 3.10+, Flask, SQLAlchemy (Flask-Login, Flask-WTF, Flask-Babel), Authlib (OAuth), Google API, Pandas, Plotly.
* **Frontend:** Server-side rendered HTML/Jinja, Bulma CSS framework, JavaScript, Plotly (charts).
* **Database:** SQLite or MySQL/MariaDB.

### Configuration Notes

* **Secret key:** The `SECRET_KEY` generated by the commands above is temporary. In production, use a fixed and secure environment variable.
* **User accounts:** Authorized personnel must be registered in the database before they can log in.
* **Google SSO:** Requires configuring `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and the appropriate redirect URI on the Google Cloud Console.
* **Gmail Notifications:** The service is enabled by default (unless `USE_GMAIL_SERVICE=False`). It requires a valid `CLIENT_SECRET_FILE` and Google API token (`TOKEN_FILE`). **Never version control these credentials.**

## Production Deployment

Deploy the application behind a production WSGI server (e.g., Gunicorn, uWSGI) or on a WSGI-compatible hosting platform like PythonAnywhere. Never use the native development server (`flask run`) in production.






# Projets LFS

## Overview

Projets LFS is a Flask web application for creating, reviewing, tracking, and analyzing educational projects at the Lycée Français de Séoul (LFS). It provides project teams and school administrators with a shared workflow for project details, approvals, budgets, collaboration, and school-year reporting.

## Features

- Create, update, duplicate, review, approve, reject, and track school projects through their status history.
- Record objectives, dates, school divisions, student groups, team members, field-trip details, links, and multi-year budget data.
- Browse and search projects with school-year and department filters, pagination, and role-aware visibility.
- Collaborate through project comments, unread-message indicators, and notification preferences.
- Review school-wide project and personnel statistics, manage database availability, and configure school-year information from the administrator dashboard.
- Analyze project data across selected school years and render charts with Plotly.
- Review budget totals and budget codes; authorized staff can manage project budget IDs.
- Manage personnel, profile preferences, notification settings, and delegated permissions.
- Generate project print views and field-trip PDFs where configured.
- Use local password login in development and Google OAuth in production. Accounts must correspond to authorized personnel records; inactive personnel cannot sign in.

The dashboard, budget, personnel administration, approval actions, and delegation controls are role-restricted. Some edit and approval operations are also disabled while the project database is locked.

## Tech Stack

- **Backend:** Python, Flask application factory, Jinja templates, Flask-Login, Flask-WTF/CSRF, Flask-Babel, SQLAlchemy/Flask-SQLAlchemy, Authlib OAuth, Google APIs, Pandas, and Plotly.
- **Frontend:** Server-rendered HTML with Jinja, local Bulma CSS, project styles, and JavaScript; Plotly is used for interactive charts.
- **Database:** SQLite by default in development (`sqlite:///db.sqlite`). Production uses the SQLAlchemy URI configured through `PROD_DATABASE_URI`; the repository does not pin a production database engine.

The application source requires Python 3.10+ because it uses `match`/`case` and PEP 604 union syntax. The pinned `pandas==3.0.5` dependency declares Python 3.11 or later, so installing the current dependency set requires Python 3.11+ unless that pin is changed. The current workspace was checked with Python 3.14.8. Flask is imported by the application but is not listed directly in `requirements.txt`, so the setup commands install it explicitly.

## Production Deployment

Deploy behind a production WSGI server or platform WSGI integration; PythonAnywhere is one possible host, not a deployment configuration included in this repository. A WSGI entry point can expose the application factory as `application`:

```python
from project import create_app

application = create_app()
```

Configure `FLASK_ENV=production`, a strong persistent `SECRET_KEY`, and `PROD_DATABASE_URI` in the hosting environment. Production startup fails if `PROD_DATABASE_URI` is unset. Use HTTPS, restrict access to secrets and uploaded/runtime files, provide persistent storage for configured data paths, and arrange database backups and operational logging.

Production does not call `db.create_all()`, and no migration framework or production schema bootstrap is included in the repository. Provision and migrate the database through a deliberate deployment process before serving traffic; do not rely on development startup to prepare production tables. Production Google sign-in also requires configured OAuth credentials and valid redirect settings. If Gmail is enabled, provision the Gmail client credentials, a valid token, and `APP_EMAIL`; otherwise explicitly disable Gmail with `USE_GMAIL_SERVICE=False`.

The repository has no PythonAnywhere or other WSGI deployment manifest. Verify the host's WSGI configuration, environment-variable support, Python compatibility, database driver, and persistent file paths before deployment.
